## 🎯 О проекте

Плагин создан **специально для IDE Google Antigravity**.

Идея родилась из нехватки наглядной телеметрии контекста и нативного аналога команды **/compact из Claude Code**. 
В Antigravity разработчик долгое время находится в «слепой зоне»: нет видимого счетчика токенов, непонятно, сколько памяти занято (20k или 250k), почему агент замедляет ответы и когда именно сработает сжатие.

**Context Monitor** решает эту проблему:
1. **Token Weather (Живая погода токенов):** процедурный фон на Canvas 2D и синхронизированная шкала, меняющая состояние в зависимости от наполнения памяти:
   - **⛅ 0–40% — Облачно:** спокойное лазурное небо, плывущие облака, минимальный расход памяти.
   - **🌧️ 40–70% — Дождь:** стальное небо, реалистичные капли дождя, рекомендация готовить Handoff.
   - **⛈️ >70% — Шторм:** свинцовые тучи, ливень, реалистичные вспышки молний, предупреждающий красный импульс.
2. **Прогнозирование Auto-compaction Antigravity:** рассчитывает адаптивную скорость сгорания контекста (Burn Rate), отображает янтарную засечку порога на шкале и заранее предупреждает, сколько шагов осталось до принудительного сжатия.
3. **Safe Handoff в 1 клик:** формирует чистый архитектурный срез задачи и запускает новый изолированный диалог со сбросом накопившегося балласта сессии, передавая новому агенту актуальный статус проекта.

## 🧠 Как работает нативный Auto-compaction в Antigravity vs Новый чат (Safe Handoff)

В Antigravity встроен собственный механизм автоматического сжатия истории (**Auto-compaction / Truncation**). Когда диалог разрастается до критического размера, платформа автоматически сжимает сессию. 

### Что Antigravity делает под капотом при Auto-compaction:
* **Порог срабатывания (~250k токенов):** для моделей семейства Gemini (окно 1.0M) системный триггер срабатывает при достижении границы в **~250 000 токенов** (буфер $2^{18} = 262{,}144$, или ~25% от окна).
* **Перезапуск сервера среды (`Server Restart`):** в момент сжатия платформа принудительно останавливает активные фоновые процессы, демоны и сабагенты (в логах фиксируется системное событие `[Notice] All your subagents and background tasks have been stopped due to server restart`).
* **Фоновая суммаризация:** отдельный процесс формирует блок `<CONTEXT_SUMMARY>` (выжимка целей, шагов и состояния), а сырая история предыдущих сотен сообщений отсекается из промпта.
* **Старт со скрытым балластом:** после сжатия контекст не падает до нуля — следующий запрос к модели отправляется с объемом **~30k–55k токенов** (сводка + системные правила + кэш инструментов).

### ⏱️ Прогнозирование момента сжатия в реальном времени

Вместо того чтобы сталкиваться со внезапным сбросом памяти врасплох, плагин ведет непрерывный предиктивный расчет:
* **Аппаратные пороги моделей:**
  - **Gemini (1.0M):** порог **~250k токенов** (буфер $2^{18}$, янтарная засечка на **25%** шкалы).
  - **Claude (200k):** порог **~160k токенов** (80% окна модели, янтарная засечка на **80%** шкалы).
* **Адаптивный Burn Rate:** бэкенд на лету анализирует средний прирост токенов за последние шаги сессии из `transcript.jsonl` (в среднем ~5k–10k за сообщение).
* **Счетчик шагов до сжатия:** наглядный блок `⚡ Авто-компакт Antigravity` со счетчиком `~X шагов` и точным остатком токенов до границы сброса.
* **Штормовое предупреждение (`forecast-alert`):** при остатке менее 25k токенов блок начинает пульсировать предупреждающим коралловым цветом: *«⚠️ ~1-2 шага. Рекомендуется Safe Handoff»*, позволяя зафиксировать срез до срабатывания гильотины авто-компакта.

### Сравнение: Auto-compaction против Safe Handoff (Новый чат)

| Характеристика | Нативный Auto-compaction (Antigravity) | Новый чат через Context Monitor (Safe Handoff) |
|---|---|---|
| **Удобство в моменте** | **0 действий:** не прерывает работу, происходит автоматически в фоне. | Требует клика по кнопке Handoff и открытия нового диалога. |
| **Стартовый объем памяти** | **~30k–55k токенов** (остаточный кэш и сжатая история сессии). | **Базовый контекст** (чистый старт без накопленного балласта старых логов и вызовов инструментов). |
| **История и артефакты** | Сохраняет `conversation_id` и доступ к полному архиву `transcript.jsonl`. | Начинает сессию с чистого листа с переносом только актуальной сути. |
| **Контроль над ТЗ** | Автоматика сама решает, что оставить в резюме, а что вырезать. | **Разработчик видит сводку**, может поправить акценты и задачи перед стартом. |
| **Фоновые процессы** | Аварийный сброс всех subagents и background tasks. | Осознанное завершение шага без внезапных сбоев процессов. |

### В каких случаях Новый Чат через плагин объективно лучше автоматического сброса:

1. **Смена крупной фазы проекта (Защита от контекстного загрязнения):**
   Если вы закончили 2 часа верстки UI с Canvas-анимациями и переходите к разработке серверной логики или БД, тащить за собой 50k токенов описания CSS-стилей и капель дождя — чистый мусор для внимания модели. В новом чате LLM на 100% сосредоточена только на бэкенде.
2. **Разрыв цикла ошибок («Error Bias»):**
   Если агент до компактизации запутался в сложном баге и сделал несколько неудачных попыток, авто-компакт сохранит следы этих ошибок в сводке. Модель продолжит ходить по кругу. Новый чат — единственный способ жестко сбросить галлюцинацию.
3. **Модели с коротким контекстом (Claude 3.5 Sonnet / Opus — 200k):**
   Авто-компакт Antigravity калиброван под окно Gemini (1.0M, порог 250k). При работе с Claude лимит 200k наступает раньше — сессия рискует завершиться аварийной ошибкой `context_length_exceeded` до того, как Antigravity успеет сжать контекст. Тумблер `Claude (200k)` в плагине вовремя предупредит о шторме.
4. **Максимальная скорость отклика (TTFT):**
   Новый чат обрабатывается моделью значительно быстрее, чем раздутая сессия с многоуровневыми историческими зависимостями.

## ✨ Ключевые возможности

| Функция | Описание |
|---|---|
| **Честный расчет метрик** | Считывает аппаратные `input_tokens` и `cache_read_tokens` напрямую из системного журнала `transcript.jsonl`. |
| **Прогноз Auto-compaction** | Янтарная засечка порога на шкале (25% / 80%) и точный счетчик оставшихся шагов до сжатия с адаптивным Burn Rate. |
| **Живой Canvas 2D фон** | Процедурное небо, дрейфующие облака, физика капель дождя (3 слоя глубины) и реалистичные ветвящиеся молнии с минимальной нагрузкой (<0.5% CPU). |
| **Цветовая синхронизация** | Цвет крупного процента, прогресс-бара и погодного бейджа синхронно переключаются между Cyan (Облачно), Ice Blue (Дождь) и Rose Crimson (Шторм). |
| **Пресеты Gemini (1.0M) и Claude (200k)** | Переключение в 1 клик с сохранением в `settings.json` и моментальным пересчетом шкал и порогов. |
| **1-Клик Safe Handoff** | Быстрая генерация сфокусированной выжимки задачи через фоновый вызов Gemini API либо через локального агента. |
| **Нативный Sidecar SDK** | Работает прямо в правой боковой панели (Aux Pane) на официальном SDK Antigravity без внешних зависимостей. |

## 🚀 Быстрая установка

### Способ 1: Через Git (рекомендуется)

Клонируйте репозиторий напрямую в каталог плагинов Antigravity:

**Windows (PowerShell):**
```powershell
git clone https://github.com/ВАШ_ЛОГИН/context-monitor.git "$HOME\.gemini\config\plugins\context-monitor"
```

**macOS / Linux:**
```bash
git clone https://github.com/ВАШ_ЛОГИН/context-monitor.git ~/.gemini/config/plugins/context-monitor
```

### Способ 2: Вручную

1. Скачайте репозиторий архивом (ZIP).
2. Распакуйте папку `context-monitor` в директорию плагинов:
   - **Windows:** `C:\Users\<Ваш_Пользователь>\.gemini\config\plugins\context-monitor`
   - **macOS / Linux:** `~/.gemini/config/plugins/context-monitor`
3. Перезапустите Antigravity (или выполните перезагрузку плагинов).

---

## 🎮 Использование

1. Откройте правую панель (**Aux Pane**) в Antigravity.
2. Выберите виджет **Context Monitor**.
3. Выберите пресет используемой модели: **Gemini (1.0M)** или **Claude (200k)**.
4. Наблюдайте за погодой контекста во время работы — виджет опрашивает лог каждые 5 секунд.
5. При достижении зоны дождя или шторма нажмите **«Сформировать срез и начать новый диалог»** для чистого перехода к следующему этапу.
